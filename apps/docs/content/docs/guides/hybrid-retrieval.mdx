---
title: Hybrid retrieval use cases
description: Combine lexical, semantic, graph, memory, and chunk retrieval.
---

Hybrid retrieval is useful when users phrase a question differently from the source, while exact terms and graph context still matter. `planet.query` fuses keyword graph-node matches, semantic graph matches, keyword document chunks, and semantic document chunks according to the selected paths.

## Run a query

```ts
const results = await planet.query({
  text: 'What evidence supports improved forecasting?',
  search: { keyword: true, vector: true, graph: true },
  filters: { nodeType: 'experiment', metadata: { team: 'research' } },
  expand: { relationDepth: 2 },
  includeEvidence: true,
  asOf: new Date(),
  limit: 10,
});

for (const result of results) {
  console.log(result.node.name, result.score, result.sources, result.evidence);
}
```

If `search` is omitted, keyword, vector, and graph options default to enabled. Semantic paths require embeddings and vector storage. Chunk vector search additionally requires a vector route and chunk store. Keyword and semantic paths run concurrently; results are fused by node ID and sorted deterministically before the result limit.

## Filters and expansion

Available filters include `nodeType`, metadata, `agentId`, and `documentId`. Relation expansion follows graph edges from semantic candidate nodes; for keyword-only graph retrieval, enabling graph search expands the keyword seeds. Set `relationDepth` deliberately: larger neighborhoods return more context and can increase query cost. `asOf` constrains graph traversal to facts valid at that time.

`includeEvidence` controls evidence in returned results. Document chunk matches return `sources` containing document/chunk identifiers. The API layer should still enforce its own document permission checks before displaying linked source material.

## Customize ranking

`retrieval.ranker` can reorder graph-search results; `queryRanker` can reorder fused query results. These are application policy hooks that run after retrieval and before the final limit. Keep them deterministic if repeatability matters, and avoid treating a score as calibrated probability unless your own ranking policy defines it that way.

## Search memories separately

`planet.query` returns graph/document knowledge results; use `planet.memory.search` for owner-filtered memory records. The `agentId` query filter restricts memory nodes in hybrid query, but should not replace explicit user/session filters and authorization in a personalized-memory workflow.

The Elysia API exposes `/v1/query` and `/v1/query/page`; SDK users can use `queryPage` for cursors.
