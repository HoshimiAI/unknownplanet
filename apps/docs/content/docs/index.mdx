title: Unknown Planet
description: An AI-native database orchestrator for storage routing and knowledge workflows.
---

Unknown Planet gives an application one TypeScript client for AI-native data workflows. It routes graph, vector, document, memory, evidence, blob, SQL, and operational storage capabilities to providers, so a deployment can combine databases behind one API while keeping each provider's native strengths.

The core workflow is **ingest → retrieve → cite**: ingest source material, retrieve relevant graph and vector results, then return evidence linked to the source. Planet coordinates those steps and routes each operation; the application owns database migrations, indexes, constraints, authorization, and source access policy. Start with [document ingestion](/docs/guides/document-ingestion), [hybrid retrieval](/docs/guides/hybrid-retrieval), and [evidence and time](/docs/guides/evidence-and-time).

## Packages

| Package | Purpose |
| --- | --- |
| `@unknown-planet/core` | Storage-neutral domain types and provider contracts. |
| `@unknown-planet/sdk` | `Planet` client, routing, ingestion, and retrieval. |
| `@unknown-planet/postgres` | PostgreSQL stores, including pgvector support and migrations. |
| `@unknown-planet/mongodb` | MongoDB stores and Atlas Vector Search adapter. |
| `@unknown-planet/redis` | Queue, stack, and key/value stores. |
| `@unknown-planet/sqlite` | Embedded graph and evidence stores. |
| `@unknown-planet/neo4j` | Graph and evidence stores. |
| `@unknown-planet/qdrant` | Vector store. |
| `@unknown-planet/minio` | S3-compatible blob store. |

Unknown Planet orchestrates providers and composes AI data workflows. Applications own their database infrastructure, credentials, and deployment policy. Provider routes remain explicit; Unknown Planet does not replicate data between databases.
